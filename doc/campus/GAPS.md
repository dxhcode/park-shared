# 阶段一缺口

当前是可点击的前端原型，用来演示信息结构和主路径。下面是还没做、或做了也会误导的部分。

## 没有后端

- 没有接口、数据库、账号体系和文件服务。登录不校验密码，任意非空账号都能进；三个名片只改变姓名和职务。
- 报修、账单和其余台账写在本机 `localStorage`。换浏览器、清站点数据或点「恢复示例」，改动就没了。
- 用户、角色、菜单台账不会改变真正的登录账号、权限或左侧导航。
- 大屏数字是按园区写死的虚构序列，不会随管理端的派单、收款一起变。

## 一套台账，三套驾驶舱

- 管理端示例始终是临港智慧园区的楼宇、企业和工单。
- 大屏另有滨江云栖科创园、临港智造产业园、光谷生命科学园。换园只换驾驶舱，不换后台列表。
- 顶栏「驾驶舱 · 云栖 / 临港 / 光谷」表示下次跳进哪座大屏，不是后台数据已切换。

## 页面能力的边界

- 能源管理端只有表计读数。曲线在大屏「能耗监测」。
- 安防没有视频流、回放或告警联动，只有点位状态。通行大屏上的点位是示意。
- 没有黑名单、闸机、发票、合同扫描件、催缴工单和支付渠道。收款只是在账单上追加一条本地记录。
- 地图是本地 SVG，不接地图服务，也不能下钻到真实楼层。
- 通知铃铛是四条固定链接，不是消息中心。
- 系统设置里的菜单即使改了路由，侧栏也不会变。

## 演示环境差异

- 本地管理端 `http://localhost:5173/` ，大屏 `http://localhost:5174/` 。端口不同，登录态不共享。
- GitHub Pages 同域，大屏「演示解锁」写入的会话，管理端可以接着用。键名是 `park-campus-session`。
- 深层地址刷新依赖站点根上的 `404.html` 把路径和查询参数送回对应应用。这只在 GitHub Pages 这种用 404 回退的托管上有效。

## GitHub Pages 还要在仓库里点一次

构建产物在 `dist` 分支根目录，不在默认分支。自动化令牌不能改 Pages 设置。若站点仍是 404，需要有权限的人打开：

https://github.com/dxhcode/park-campus/settings/pages

1. Build and deployment 选 **Deploy from a branch**
2. Branch 选 `dist`，文件夹选 **/ (root)**，保存

保存后的地址：

- https://dxhcode.github.io/park-campus/
- https://dxhcode.github.io/park-campus/admin/
- https://dxhcode.github.io/park-campus/screen/

源分支或目录不对时，这三个地址都会 404。保存之后短时间 404，是 GitHub 还在做第一次部署。

## 不在这一阶段的范围

权限分级、审批流、导入导出、打印、消息推送、真实计费、设备接入、多园区后台数据隔离，都还没有。演示脚本见 [DEMO.md](./DEMO.md)。
