# 第一期缺口

这是政府管理端的前端原型，用来走查界面和演示路径。下面是现在还没做、或做了但不要当成真系统的部分。

## 没有后端

- 没有接口、数据库、登录服务和文件服务。
- 管理端两份数据都在本机 `localStorage`：企业、用房、闲置是 `park-gov.registry.v1`，其余台账是 `park-gov.affairs.v1`。会话是 `park-gov.session`。
- 退出登录不会清台账。顶栏「恢复样例数据」会把两份台账一起还原。
- 换浏览器、换域名或清除站点数据后，改过的内容消失。
- 本地开发时管理端在 5173、大屏在 5174，两边的 `localStorage` 不共享。GitHub Pages 上两者同源，但大屏仍然不读这两份键。

## 大屏是独立快照

- 大屏的园区、企业、风险、投诉和考核数字写在 `apps/screen-app/src/mock/dashboard.ts`，与管理端样例对齐，但不是同一份运行时数据。
- 在管理端新建企业、改风险分、办结投诉，大屏上的环、条、地图和滚动字幕都不会变。
- 地图是示意图，不是地理底图，不能缩放、测距或落到真实坐标。
- 图表是页面里的 SVG 和 CSS 动画，没有图表库，也没有时间序列接口。

## 账号和权限

- 只有三个写死的演示账号，密码 `Park@2026` 直接印在登录页上。没有验证码、没有口令重置、没有单点登录。
- 陈启明、周岚、刘澄看到的菜单完全一样。系统设置里的组织和角色只是台账说明，不会拦截路由或按钮。

## 页面能力的边界

- 统计分析只维护报表标题和文字摘要。状态里的「可导出」不会生成文件。图形在大屏。
- 政策没有正文、附件和生效范围计算。数据报送没有实际上报，回执号是样例字符串。
- 投诉、考核、告警没有消息、催办或审批流。列表上的状态是手改字段。
- 新建和编辑会做前端校验（必填、日期格式、电话位数），没有服务端校验，也没有并发冲突处理。
- 筛选、分页都在浏览器里完成。样例只有十几条，没有万级列表、没有服务端排序。
- 删除没有单独入口。要回到初始数据，用顶栏「恢复样例数据」。

## 样例本身

- 滨江云栖、临港智造、光谷生命，以及企业名、电话、统一社会信用代码、文号、金额都是虚构的，不能拿去对接真实法人库。
- 信用代码带 `MOCK`，用来标明不是真实主体。
- 大屏和管理端的件数、分数是为演示凑齐的，不是从台账实时汇总的。若样例以后只改一边，讲解时会看到对不上的数字。

## GitHub Pages

- 发布脚本只推 `dist` 分支，不能改仓库的 Pages 设置。
- 站点要上线，必须在 GitHub 仓库 Settings → Pages → Build and deployment 里选择 Deploy from a branch，Branch 选 `dist`，Folder 选 `/ (root)`。
- 预期地址：
  - https://dxhcode.github.io/park-gov/
  - https://dxhcode.github.io/park-gov/admin/
  - https://dxhcode.github.io/park-gov/screen/
- 应用的 Vite `base` 是 `/park-gov/admin/` 和 `/park-gov/screen/`。若 Pages 没配对，或仓库改名，静态资源和路由都会错。
- 深层地址刷新依赖根目录 `404.html` 把路径带回应用。这是静态托管的变通，不是服务端重写。

## 还不在这期里的东西

- 真实地图、物联网告警、视频、电子签章、公文交换。
- 打印、Excel 导出、批量导入。
- 多园区权限、操作审计、与市级平台的数据对账。
- 大屏按管理端当前筛选联动，或管理端嵌入大屏图表。
- 移动端专用布局。窄屏能用，但大屏按桌面讲解来排。
